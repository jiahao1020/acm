## acm（Agent Config Manager）代码审查

对 `D:\study\acm` 做了系统化审查（非改动，只读 + 沙箱探测）。

**项目定位**：Node CLI，把 MCP server 配置 / API 网关 key / Skills 同步到 14 个 AI 编程客户端。TS + tsup + commander 15 + @clack/prompts，Node >= 22.12（依赖纯 ESM）。

**验证结果**：`tsc --noEmit` 通过；58 个单测全绿；无 git 仓库（未纳版本控制）；dist 已构建。

**架构优点**：适配器模式清晰（简单客户端用 spec 数据表驱动，特殊的单独实现：Codex/TOML、OpenCode 非标 schema、Claude Code 双文件）；原子写入 + `.bak` 备份；解析失败抛 ConfigParseError 绝不降级为空配置（这点做得比多数同类工具好）；技能名路径逃逸防护 + 测试覆盖。

**发现的问题（按优先级）**：
- P0-1 `src/index.ts:14` readVersion 用 `path.join(__dirname,"..","package.json")`，dev 下 __dirname=src → 指向 D:\package.json（不存在）；且 files:["dist"] 打包时根 package.json 实际在 dist 上一层，能解析（实测 Case B=1.0.0）。真实风险是 dist 被单独拷贝时静默回退 0.0.0。应改为 tsup define 注入或 createRequire 从 package 根解析。
- P0-2 `src/commands/mcp.ts:62-103` mcpList 无 try/catch，任一客户端配置不可解析则整个 list 中断（实测：健康客户端的结果也不打印）。应参照 mcpSync:342-356 的 unreadable 收集模式。
- P1-3 `src/commands/mcp.ts:43-56` canonical()/sameServer 用 JSON.stringify 比较，`{a:undefined}` vs `{}` 返回 false（实测）→ 重复 add 误报冲突并要求 --force。
- P1-4 `src/skills/base-skill-adapter.ts:61-73` installSkill 只写 `skillsDirs()[0]`，removeSkill 删全部 roots → ZCode（`.zcode/skills` + `.agents/skills`）install→list→remove 不对称，且残留副本会污染后续 sync 比对。
- P1-5 适配器写回不保留未建模字段：claude-desktop/cursor/windsurf/workbuddy/base-json-adapter/claude-code 均整对象替换 `mcpServers`；OpenCode 的 toOpenCode 主动丢弃 cwd（实测 `--cwd` 对 opencode/codex 静默失效）；ZCode/OpenCode 保留（实测 ZCode 连未知字段都保留）。建议写入时深合并已有条目，并给 ClientAdapter 加 `supportedFields` 声明能力矩阵。
- P2-6 `--client ,,,` → selectClientIds 过滤空串后 targets=[] unknown=[] → 调用方当成"没有可用客户端"（实测）。应报"空 id 列表"。
- P2-7 `.bak` 累积：backupFile 无限覆盖同一 `.bak`，且 CLI 自己生成的 `.tmp`/`.bak` 可能被客户端/Norton 当可疑文件；建议 `.bak` 带时间戳并在成功后清理或加保留策略。
- P2-8 README 安装指引 `npm install -g .` 未说明 Windows 需在 Developer Mode 或管理员权限下建 bin shim。
- P3-9 `src/commands/key.ts:171` 与 `:154` 文案重复（兼容"未检测到"与"已检测但无文件化 API 配置"两种情形，可提取函数）。
- P3-10 `src/utils/atomic-write.ts:26` 固定 `filePath + ".tmp"`，并发运行两个 acm 实例会互踩；建议 mkdtemp 或 pid/随机后缀。
- P3-11 无 CI 配置、无 git 仓库；`scripts/make-sandbox.js` 无 npm script 暴露，需手动 node 调用；`.sandbox/`、`.test-build/`、`dist/` 应入 gitignore。

**改进建议方向**：能力矩阵（capability matrix）声明式校验 + 缺失能力时告警而非静默跳过；`--json` 输出便于脚本化；`acm doctor` 汇总诊断；`--yes` 覆盖 mcp remove；`acm skill sync` 缺来源时的显式警告。
